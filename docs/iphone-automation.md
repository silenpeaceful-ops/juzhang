# iPhone 自动录入：建行短信方案

**当前是配置设计，尚未安装或启用。** 聚账后端已能接收并识别交易文本，手机自动转发仍待完成。本文没有密钥，也没有可直接导入的快捷指令安装包。

## 已核实的入口

实际手机已进入“快捷指令 → 自动化 → 新建 → 信息”，看到发件人、“信息包含”和“立即运行”。Apple 官方说明“信息”触发条件可以按发件人及文本筛选，多个条件需同时满足。[Apple 通信触发条件](https://support.apple.com/zh-cn/guide/shortcuts/apdd711f9dff/ios)

本次目标银行是建设银行。官方公告列出 `95533` 与 `106980095533` 两个通知号码，并说明账户变动短信存在分批切换；以本人实际收到的号码校准。仅筛选号码不足以区分交易与验证码，应再筛选正文。[建行官方号码公告](https://www2.ccb.com/chn/2025-08/22/article_2025082211005979812.shtml)

任意微信 / 支付宝 App 通知能否触发并提供完整正文，尚未在当前手机验证。Apple Pay 交易入口也不能作为已覆盖微信零钱和支付宝余额消费的证据。

## 准备接收快捷指令

1. 在本人登录后的聚账“接入”页获取专属接口地址、请求头与样例。目的地为本人私有网站的 `/api/ingest`。
2. 从“快捷指令输入”取得这次短信正文，实际运行时核对变量是否包含正文；不要读取历史短信、通讯录或其他聊天。
3. 先跳过验证码、动态口令等认证消息，再限定消费、支出、扣款、转账、退款等交易词和可识别金额。非交易短信在手机端终止，不发送。
4. 触发开始时记录接收时间，生成事件 ID 并保存为变量。同次请求的重试复用这些变量。
5. 添加“获取 URL 内容”，选择 POST / JSON，使用接入页给出的请求头和下面的字段。
6. 检查响应的 `ignored`、`duplicate`、`review` 或错误，只向本人显示必要状态，不将正文或密钥放入公开日志。

| JSON 字段 | 类型 | 值 |
| --- | --- | --- |
| `text` | 字符串，必填 | 筛选后的交易短信正文变量 |
| `channel` | 字符串 | `bank` |
| `occurredAt` | ISO 8601 字符串，可选 | 可靠交易时间，或本次接收时间；明确时区，例如 `+08:00` |
| `eventId` | 字符串，可选，建议填写 | 每个消息事件生成一次，网络重试复用 |

下面仅为合成示例，实际快捷指令要使用变量：

```json
{
  "text": "建设银行：支出人民币18.50元，消费示例商户",
  "channel": "bank",
  "occurredAt": "2026-10-13T12:00:00+08:00",
  "eventId": "example-event-id"
}
```

请求头包含 `Content-Type: application/json`；服务配置另有 `OAI-Sites-Authorization` 与 `X-Juzhang-Key`。使用本人接入页的完整配置，不将密钥放进 URL 参数、GitHub 或公开分享链接。

`eventId` 保证同一消息重试仍是同一事件。若系统把同一消息作为新触发运行并生成不同 ID，仅靠这个字段不能去重，还会依赖订单号 / 文本规则；没有稳定事件来源时应保留核对机会。

## 连接个人自动化

1. 完成可审查的接收快捷指令，用合成文本核对字段。合成文本发送到真实账本也会生成记录，测试后需标记并删除测试记录。
2. 新建“信息”自动化，限定建行发件人。若界面只能设一个号码，可分别创建两个相同流程。
3. “信息包含”按真实文案设条件，不要只匹配单一交易词而漏掉退款 / 转账；更完整的筛选放在接收快捷指令内。
4. 运行接收快捷指令并传入本次消息正文，核对输入变量。
5. 启用前，由本人确认仅将筛选后的交易财务正文发到本人私有聚账用于自动记账。再按当前 iOS 界面选择立即运行，核对锁屏、网络与首次访问权限。
6. 等待本人正常使用产生交易通知，核对触发、金额、来源、时间、重复消息和待核对状态；不必主动转账或消费来测试。

## 聚账的处理规则

| 消息情况 | 处理 |
| --- | --- |
| 成功消费且金额可识别 | 保存已确认支出 |
| 余额 / 额度、验证码、推广、失败交易 | 忽略 |
| 待收款、未到账、处理中 | 待核对，不进入确认汇总 |
| 明确转账入账或本人已收款 | 收入 |
| 向他人转账、用途不明 | 待核对，对方收款完成不是本人收入 |
| 充值、提现、还款、自有账户转移 | 账户转移，不增加消费 |
| 绑卡支付与银行扣款疑似同一笔 | 保留待核对，不静默删除 |

规则已用合成文本测试，实际建行格式仍需验证。缺少必要信息时先保留补账方式，再以样例增加规则测试。

## 覆盖范围

建行短信只覆盖银行确实发送通知的交易；微信零钱、支付宝余额消费可能不产生银行卡短信。完整汇总还需验证新的交易采集入口，或用官方 CSV / 手动补录。交易邮件也可作为后续入口，本次尚未配置。

每日清单独立于手机采集，读取账本已存交易，在北京时间 21:00 生成昨天完整清单。真实微信接收凭据未配置，已有调度不等于微信已收到消息。
